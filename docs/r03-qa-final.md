# R03 frozen candidate QA

Candidate: `work/r03-01-xp4`, catalog: `work/r03-final-catalog.json`. Independent static and binary audit **passes** for all 550 adapted records in 54 scenes, preserving the 266 R02 records. This does not establish an in-game route traversal.

The manifest reports `section_candidate`, `candidate_ready`, no blockers or deferred scenes, and runtime verification false. The final plan, catalog and bible fingerprints independently match their frozen files. Original Opening/System hashes match the manifest. The source closure has 67 entries and 56 text entries, all required by the plan; the new bridge service menu and its reachable failure branches are included. See [source inventory](r03-qa-source-inventory.md) and [editorial review](r03-qa-editorial.md).

All six HDMs retain their original 1,261,568-byte size. Data, Ending, User and Visual are byte-identical to the originals. Opening SHA-256 is `a158aaab22da5da99bd236269def1e4022440aafb435b39db353d658ce01954f`; System SHA-256 is `71b93850ac80c62a6c2c828da6f74e99680b7801ff5fbf0c79f4a0fd28c1ac8c`. Both match the manifest. Independently parsed distributable IPS files contain 209 Opening records and 632 System records, in ascending order without overlap. Applying each patch to its original image reproduces the exact candidate and reaches the EOF marker with no trailing data.

A fresh original-based combined compilation selected all 550 records. All 722 reported patch ranges match the frozen candidate after accounting for the documented XP4 reward-heading override. The 64-byte trainer routine at System `0x785e..0x789d` exactly matches independently generated XP4 code, its SHA-256 and the unchanged R02 trainer metadata. Its 26-byte heading matches BASE REWARDS. All 266 carried R02 canonical texts and in-game adaptations are unchanged. The R02-to-R03 differences—521 Opening bytes and 6,911 System bytes—are confined to the cumulative compiler patch ranges, previous menu relocation ranges, and the two reviewed box/selection width changes. New menus may relocate earlier English menu strings inside the guarded pool; preservation was checked through compilation, pointers and text rather than assuming fixed pool addresses.

The final name-table scan resolves all 280 development item/equipment IDs to English labels of at most nine cells. Full-width numeric calibers normalize to the intended ASCII digits. The 220 new source strings reuse prior translations for the remaining 18 unique labels; all exact aliases and overlapping suffixes are covered by guarded allocation. Existing name pools and unowned pointer/string pairs passed the dedicated preservation tests. The numeric progression table `0x1055c..0x10798` and all equipment/stat data at `0x11800..0x13fff` are byte-identical to the originals. Availability thresholds, stats and crafting rules were not modified. The overbroad pointer-scan error involving `0x10594` was corrected before candidate construction and is covered by regression checks.

All 16 focused R03 flow, UI, location and equipment tests passed. The ship service overlay's single-cell blank encoding, dynamic item/amount/choice fields, immutable Joe header, and paired menu/highlight widths received independent source review. QA found and closed the additional heavy-equipment unload warning at System `0x209a`; the final build includes it.

The audit result is recorded in ignored `work/r03-qa-frozen-audit.json`, with the reproducible audit script at `work/r03-qa-audit.py`. Any separate boot smoke test must be reported as boot evidence only.
